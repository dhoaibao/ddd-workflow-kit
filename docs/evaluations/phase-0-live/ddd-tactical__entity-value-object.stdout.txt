   - **Failure cases:** No specific failure policy was supplied.
   - **Counterexample prevented:** A contact-detail change must not create a new customer identity.
   - **Acceptance signal to define:** Before and after the change, the customer reference resolves to the same customer identity.
   - **Affected relationship:** Customer access supplies the identity reference.

2. **Compare two monetary amounts**
   - **Actor:** Billing workflow or caller.
   - **Precondition:** Both amounts have valid currencies and precision.
   - **Input:** Two monetary amounts.
   - **Decision:** Compare by currency and numeric value.
   - **Successful outcome:** Amounts are equal only when both currency and numeric value are equal.
   - **Failure cases:** Invalid currency or precision; exact handling is not specified.
   - **Counterexamples prevented:**
     - Numerically equal amounts in different currencies are not equal.
     - Amounts with invalid currency or precision are not valid monetary amounts.
   - **Acceptance signal to define:** Equality returns true only for matching currency and numeric value.
