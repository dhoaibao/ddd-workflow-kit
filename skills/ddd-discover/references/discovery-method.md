# Lean discovery method

## Frame one decision

Ask only what can change the selected increment: outcome, capability boundary, out-of-scope behavior, costly decisions, mode, evidence access, owner, and simpler alternative.

## Use examples

Record actors, commands/decisions, preconditions, success/failure examples, exceptions, terms, obligations, and observed behavior. For brownfield work, compare tests/operations/contracts with desired policy. Code structure is current implementation evidence, not a domain boundary.

## Fit decision

Use `fit` when rules, ambiguity, costly change, meaningful integration, or differentiation justify a focused model; `limited-fit` for one capability; `not-fit` when simpler CRUD is sufficient. Record the evidence and the signal that would reopen it.

## Conditional depth

Create assessment, vision, or language only when the trigger is present. A one-context flow should not receive a whole-domain catalogue. Omit empty assumptions/questions and generic teaching.

## Handoff

Discovery hands one strategic request only when scope, outcome, terms, material claims, owner, and evidence support boundary work. Otherwise stop with the smallest missing decision or evidence. Never mark inference validated or claim a later stage ran.
